# FreeNote（Windows 桌面版）

FreeNote 的桌面端：与 Android 版（`../android`）相同的便签功能与数据格式，
支持两种同步方式——**局域网 P2P 直连**（无需服务器）与 **FreeNote 服务端中转**（可跨网络）。
两种协议都与 Android 版完全互通，可以同时开启。

> 目录结构：`freenote/android`（安卓端）、`freenote/windows`（本 Windows 端）、
> `freenote/server`（同步服务端）。

## 与 Android 版的互通方式

| | FreeNote（Windows） | FreeNote（Android） |
| --- | --- | --- |
| P2P 同步 | 内置 HTTP 同步服务 + UDP 组播发现 | 同一协议（App 前台运行时监听） |
| 服务器同步 | 连接 FreeNote 服务端（`../server`） | 同一协议、同一账号 |
| 认证 | P2P：相同的同步账户 + 相同的「同步口令」；服务器：用户名 + 密码 | 同 |
| 数据格式 | 两端完全一致（`notes.db`、JSON 备份、锁定便签加密算法） | — |

## 功能

- 便签：标题、正文、8 种颜色、置顶、标签、回收站（30 天自动清除）
- 文件夹：左侧文件夹树管理嵌套文件夹（新建/重命名/删除），便签归属单个文件夹并随同步传播；
  删除文件夹只把便签上移到上级，不会删除便签；本机新建的空文件夹仅本地占位（写入便签后随同步可见）
- Markdown 实时预览、清单（Checklist）模式、字数统计、模板（会议记录/任务清单/日记/每周总结）、
  `[[便签标题]]` 双向链接（预览中点击跳转到同名便签）
- 正文内联图片：内容寻址的便携标记 `![](freenote-img:<sha256前16位>.<扩展名>)`，
  **图片随 P2P/服务器同步与 JSON 备份一起迁移**（协议 v6，与 Android 版格式一致）；
  旧版 `file://` 图片引用会在启动时自动迁移
- 单条便签导出：Markdown / HTML / TXT / PDF、打印（Pandoc 式 HTML 导出会内嵌本地图片）、复制全文
- 多选批量操作：批量移到回收站、移动文件夹、添加标签、全选
- 快速记录：全局热键 `Ctrl+Alt+N` 唤起并新建便签；托盘菜单「从剪贴板新建便签」
- 提醒通知（支持重复提醒：每天/每周/每月，到点自动排下一次）、应用锁 PIN
  （AES-256-GCM + PBKDF2，与 Android 版算法一致）
- 搜索（**解锁会话内可搜索锁定便签的加密内容**）/ 标签筛选 / 排序（升/降序）/
  时间线视图（按修改日期分组：今天/昨天/…）
- 历史版本：每次修改自动留存旧版本（同内容/5 分钟合并，最多 30 版，仅本机），
  编辑器「历史版本…」可预览并恢复，恢复前自动留存当前状态
- 导入：JSON 备份、`.md`/`.txt` 文件（每个文件一条便签，首个 `#` 标题作便签标题）、
  Evernote `.enex` 导出（按内部便签展开；附件不入库，正文以占位文字标记）、
  直接拖拽文件/文件夹到窗口
- 自动备份：按设定间隔（默认 24 小时）把全量 JSON（含图片）写入指定目录，
  只保留最近 10 份；可配置 WebDAV 地址在备份后自动上传（密码经 DPAPI 加密保存）
- **P2P 同步**：局域网自动发现、增量交换、最后写入者获胜（LWW）、删除墓碑传播、
  摘要快速通道（双方一致时不传数据）、账户隔离（服务器账号/离线账户，
  离线账户可一键生成 UUID，无需联网注册）、
  HMAC 签名认证与防重放
- **服务器同步**：登录 FreeNote 服务端（与 Android 版同一账号）跨网络同步，
  也可与 P2P 同时开启；服务端只保存密文，锁定便签的正文/标题对服务器不可见；
  支持修改密码（其他设备令牌一并失效）、注销账号（删除服务端数据，本机数据保留）

## 安装与运行

```powershell
cd freenote/windows
python -m pip install -r requirements.txt
python run.py
```

要求 Python 3.10+（开发环境 3.13）。首次运行 Windows 防火墙会询问是否允许网络访问，
选择「允许」才能让其他设备发现本机。

## 数据位置

默认在 `%APPDATA%\FreeNote\`：

| 文件 | 说明 |
| --- | --- |
| `notes.db` | SQLite 数据库（表结构与 Android Room 的 `notes` 表一致） |
| `attachments/` | 内联图片文件（正文中的图片标记引用） |
| `settings.json` | 主题、设备名、同步账户、已知设备、服务器地址等；同步口令/登录令牌/WebDAV 密码/PIN 哈希经 DPAPI 加密 |

可用环境变量 `FREENOTE_DATA_DIR` 覆盖数据目录（测试时使用）。

## 两分钟配对（P2P，Windows ↔ Android）

1. 在 Windows 上启动 FreeNote，在 Android 上启动 FreeNote；
2. **两端登录同一服务器账号**（「设置 → 服务器同步」），或都不登录服务器、在
   「设置 → P2P 同步 → 离线账户」填写**完全相同**的账户名——推荐点「生成 UUID」
   得到随机账户，点「复制」后到另一台设备粘贴，**全程无需联网注册**；
3. 在其中一台点「生成随机口令」，点「复制」，在另一台设备填写**完全相同**的同步口令；
4. 两端都勾选「设置 → P2P 同步 → 启用 P2P 同步」（网络功能默认关闭，需显式开启）；
5. 局域网内几秒内即可互相发现（设备出现在列表中），保存便签后自动同步。

组播被防火墙/路由器隔离时：在对方设备上查看监听端口（设置面板状态区显示），
用「手动添加：`对方IP:端口`」建立直连。Android 端 P2P 仅在 App 前台运行时监听。

> **同步账户**：配置了服务器地址与用户名后，P2P 自动以「服务器账号」为同步账户；
> 未配置服务器账号时使用离线账户。离线账户推荐用「生成 UUID」：随机且全局唯一，
> 不会与其他用户撞名，复制到自己的其他设备即可组成同一同步组，无需注册服务器账号。
> 账户或口令任一不同，设备之间互相不可见、无法解密：同一局域网内不同用户的数据不会互相串。
>
> P2P 协议当前为 v6（账户隔离 + 正文加密 + 同毫秒内容哈希仲裁 + 附件内容寻址同步 +
> 重复提醒字段；内容哈希含文件夹路径）。两端协议版本不一致时无法互通：
> 不会出现在发现列表，手动添加会提示「协议版本不一致，请升级」；
> **升级后需要三端（Windows/Android/服务端）都更新到支持 v6 的版本**。
> 未设置账户时按「同一口令即同组」分组，建议补填服务器账号或离线账户。

## 服务器同步（跨网络，Windows ↔ Android）

1. 在任意一台常开设备上部署 FreeNote 服务端（见 `../server/README.md`）；
2. 两端在「设置 → 同步 → 服务器同步」填写相同服务器地址，用**同一个账号**登录
   （没有账号先点「注册并登录」）；
3. 登录后自动同步一次；之后按设定的间隔自动同步，也可随时点工具栏的「立即同步」。

P2P 与服务器可以同时开启：同一账号的设备先经服务器交换，局域网内再走直连增量。

## P2P 同步原理

```
   设备 A (FreeNote)                        设备 B (FreeNote)
  ┌──────────────────┐                   ┌──────────────────┐
  │ 便签库 SQLite     │                   │ 便签库 SQLite     │
  │ 内置同步服务 :8765│ ◄── HTTP 直连 ──► │ 内置同步服务 :8765│
  │ UDP 发现 :8766   │ ◄── 组播公告 ───► │ UDP 发现 :8766   │
  └──────────────────┘                   └──────────────────┘
```

1. **账户**：每台设备属于一个同步账户——配置了服务器账号时是「服务器地址 + 用户名」，
   否则是设置里的「离线账户」（推荐一键生成 UUID）；账户作为 PBKDF2 salt 的一部分参与组密钥派生，
   账户不同的设备连发现 tag 都不同，天然互相不可见（公告本身不含便签内容）；
2. **发现**：每 8 秒向组播组 `239.255.42.42:8766` 公告
   `{设备ID, 设备名, 同步端口, 状态摘要}`，公告带「账户 + 口令」派生的 tag；
3. **加密**：请求/响应正文用组密钥（账户 + 口令派生）做 AES-256-GCM 加密
   （密文 = nonce(12) + 数据 + 校验标签(16)），网络上不出现便签明文；
4. **认证**：每个请求在密文之上再附 时间戳 + 随机数 + HMAC-SHA256 签名，
   双方校验签名；请求还携带账户指纹，账户不一致直接拒绝并提示；
   时间戳偏差超过 5 分钟或随机数重复（重放）一律拒绝；
5. **两步交换**（每步只传增量）：
   - `POST /api/freenote/manifest`：交换状态清单（`id/updatedAt/删除标记/内容哈希` +
     摘要 + 本机附件名清单），摘要相同直接结束；否则对方返回「需要你补发的 id 列表」
     与「需要你推送的附件名列表」（`wantImages`）；
   - `POST /api/freenote/exchange`：补发对方缺少的便签，同时取回自己缺少的便签，
     双方按 `updatedAt` 最后写入者获胜合并；
6. **附件**（协议 v6）：便签缓存交换完成后按清单补传图片——
   `POST /api/freenote/image_put` 推送对方要的、`POST /api/freenote/image_get` 拉取自己缺的；
   每批 ≤8 张 / ≤8MB，仍有剩余时短延迟自动续跑；附件按内容哈希校验（收到即验名）；
7. **删除**：回收站删除随正常条目传播；彻底删除以「墓碑」形式传播，
   收到的一侧保留删除态（不会被旧数据复活）；
8. **冲突仲裁**：时间戳相同（同一毫秒）时先按「删除优先」，再按内容哈希小者
   确定性仲裁——任何到达顺序下双方都收敛到同一版本，不会出现静默分歧；
9. **去重**：同步状态摘要（`id:updatedAt:isDeleted:内容哈希` + 附件引用状态
   `name:本机是否有` 的 SHA-256）用于快速判断「双方完全一致」（含图片），
   避免重复传输；「便签一致但图片缺失」的设备也会被发现并触发附件补传。

## 安全说明

- **传输加密**：P2P 组密钥由「同步账户 + 口令」经 PBKDF2-HMAC-SHA256（600000 次迭代）
  派生，正文用 AES-256-GCM 加密，签名覆盖密文；账户或口令不同的设备既无法解密
  也无法伪造/篡改报文，也不会出现在对方的发现列表里（同一局域网多用户互不干扰）；
  发现公告只含设备名/端口/状态摘要等元数据，不含便签内容；
  请使用较长的随机口令（至少 8 位，设置面板提供「生成随机口令」）：发现广播携带的匹配
  tag 理论上可被被动监听者用于离线穷举口令，高迭代成本 + 高熵口令可让穷举不可行；
- **账户隐私**：手动添加设备时探测到的「账户指纹」是账户命名空间的 SHA-256 截断哈希
  （16 位十六进制），只用于判断两端账户是否一致，不包含用户名/服务器地址明文；
- **凭据保护**：同步口令、服务器登录令牌、WebDAV 密码与 PIN 哈希不落盘明文——
  Windows 端用 DPAPI 加密存于 `settings.json`（按当前 Windows 用户隔离，复制到
  其他机器/用户下无法解密，需重新填写）；DPAPI 写盘失败时回写上一次的密文
  （绝不落盘明文，也不会把 PIN 哈希/令牌静默清空）并给出警告；
  Android 端用 Android Keystore 加密存于应用私有 SharedPreferences（随应用卸载销毁）；
- 建议在可信局域网内使用；跨公网 P2P 请先建立 VPN（如 WireGuard/Tailscale），
  再用「手动添加 `虚拟IP:端口`」的方式同步；
- **服务器同步**：服务端保存普通便签的 JSON 原文（锁定便签为密文，服务端不可读）；
  传输加密支持两种方式：服务端原生 TLS（`python run.py --ssl-certfile … --ssl-keyfile …`，
  客户端使用 https:// 地址；自签名证书需在两端客户端设置中允许）或
  Nginx/Caddy 反向代理统一上 HTTPS（见 `../server/README.md`）；
  服务器地址不带协议前缀时：内网/本机默认 http，公网域名或 IP 默认 https；
  客户端「测试连接」在检测到公网明文 HTTP 时会给出提示；
  WebDAV 备份上传会拒绝公网明文 HTTP 地址（备份含便签明文，Basic 凭据也会上链路）；
- 应用锁 PIN 与 Android 版相同：锁定便签用「随机盐 + PBKDF2-HMAC-SHA256 600000 次」
  + AES-256-GCM 加密（格式 v2，密文自带盐与迭代数；旧版固定盐 12000 次的密文仍可解密），
  PIN 为 4~12 位数字，两端需要使用相同 PIN 才能解开对方的锁定便签；
  注意：锁定便签只加密标题与正文，**标签/文件夹/颜色等元数据仍为明文**
  （跨端筛选需要明文索引；如需更强隐私请避免在锁定便签上使用描述性标签）；
- 本机 `notes.db` 中普通便签为明文（与 Android 版一致），
  请保护数据目录或启用系统磁盘加密；`settings.json` 中凭据已用 DPAPI 加密，仍请勿外传；
- JSON 备份导出的是普通便签明文（锁定便签仍为密文），备份文件请按敏感数据保管；
  自动备份目录与 WebDAV 上的备份文件同样按敏感数据保管。

## 与 Android 版的互通

- **P2P**：Android 版（`../android`）实现了与上节完全相同的 P2P 协议
  （账户 + 口令的组密钥派生、HMAC 签名与防重放、两步交换、LWW、删除墓碑），
  局域网内 Windows 与 Android 设备可直接互相发现并同步；
- **服务器**：两端都可以登录 `../server` 的同一账号，经服务端中转同步，
  实现跨网络互通；
- FreeNote 可以直接打开 Android 版导出的 `notes.db` 副本；
- 双方的 JSON 备份可以互相导入（**备份格式 v6 起包含图片附件**，会写入本机附件目录）；
- 锁定便签使用相同的加密参数（随机盐 + PBKDF2 600000 次 + AES-256-GCM，格式 v2；
  兼容旧版固定盐 12000 次密文），需要各自设置相同的 PIN 才能解密对方的锁定便签；
  注意：格式 v2 密文需要两端都是升级后的版本（协议 v7 会以版本号门控 P2P，
  旧版设备直接提示升级，不会静默把 v2 锁定便签显示成 PIN 错误）；
- 图片附件使用相同的内容寻址命名（sha256 前 16 位 + 扩展名），跨端按哈希去重与校验。

## 局限

- 所有网络功能默认关闭：全新安装不监听端口、不参与局域网发现、不自动同步；
  P2P 需要在设置中勾选「启用 P2P 同步」并填写同步口令，服务器同步需登录后，
  再按需开启发现/自动同步；
- Android 端的 P2P 监听与自动同步只在 App 前台运行时工作（息屏/切后台即停止），
  需要接收同步时请让 App 保持打开；Windows 端不受影响；
- 局域网点对点依赖设备在线：对方离线时，本机变更会在下次双方同时在线时补齐
  （自动发现触发或定时自动同步，默认 5 分钟）；
- 未登录服务器且未填写离线账户时，同一口令即视为同组；
  多用户共用同一局域网时请配置账户（服务器账号或各不相同的离线账户）；
- 服务器同步需要自行部署 FreeNote 服务端，且服务端默认明文 HTTP，
  公网部署请按 `../server/README.md` 配置 HTTPS；
- 历史版本仅保存在本机、不参与同步（恢复会产生一次普通修改并随同步传播）；
  条数上限 30 版、同内容/5 分钟内的连续保存合并；
- 自动备份在应用启动时与运行期间每 30 分钟检查一次是否到点（应用未运行期间不会执行）；
  WebDAV 上传为单文件 PUT，不处理服务端的并发冲突；
- 协议 v6 起附件参与同步；协议 v7 起锁定便签密文为 v2，升级需三端同时更新；
  旧版本设备与新版设备无法 P2P 互通（会提示升级，而不是静默解不开锁定便签）。
  服务器同步对旧客户端仍可降级为仅同步便签文本——服务端通过 `capabilities` 字段告知附件支持。
